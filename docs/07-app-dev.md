# 07. 애플리케이션 개발

### 1. 개발 순서

| 순서 | 작업 | 결과물 |
|---|---|---|
| 1 | ERD·컬럼 정의서 작성 (04 상세 설계 > 13. 테이블 기준) | `docs/db-design.md` (ERD·컬럼 정의서), Flyway 첫 마이그레이션(`V1`) |
| 2 | 화면 설계서 작성 (04 화면 7개 기준) | `docs/` 와이어프레임 |
| 3 | 백엔드 기본 구조: 공통 응답·에러 처리, 로그 형식, JWT 인증, Actuator, Swagger | 빈 API 서버 실행, `/actuator/health` 정상 |
| 4 | 기능 개발: 인증·회원 → 내 재료 → 레시피 추천(Gemini·캐시·요청 제한) → 상세·즐겨찾기·검색 기록 → 인기 랭킹 | API 25개 (04 상세 설계 > 14. API, 운영용 2개 제외) |
| 5 | 프론트 개발: 공통 레이아웃 → 로그인·회원가입 → 메인(추천) → 상세 팝업 → My Kitchen | 화면 7개 |
| 6 | 테스트 작성: 기능 개발과 함께 서비스 단위 테스트, DB·Redis 통합 테스트 작성 | CI에서 자동 실행 |
| 7 | Docker 이미지 빌드 확인 (`backend/Dockerfile`) | 로컬에서 이미지 실행 확인 |

※ 1·2번은 07 시작 시 먼저 작성 후 확정, 이후 개발 진행

### 2. 백엔드 구성

| 구분 | 선택 | 용도 |
|---|---|---|
| 기본 | Spring Boot 4.2.x (Java 21), Spring Web | API 서버 |
| 데이터 접근 | Spring Data JPA | DB 조회·저장을 자바 객체로 처리 (SQL 반복 작성 감소) |
| DB 변경 관리 | Flyway | 테이블 생성·변경을 버전별 SQL 파일로 관리, 앱 시작 시 자동 적용 |
| 인증 | Spring Security + JWT | 로그인 토큰 발급·확인, 회원 전용 API 보호 |
| 캐시 | Spring Data Redis | 추천 캐시, 요청 제한, 인기 랭킹 |
| 입력 검사 | Bean Validation | 요청 값 형식 검사 (빈 값, 길이 등) |
| 외부 호출 | RestClient (Spring 기본) | Gemini API 호출, 타임아웃 30초 |
| 운영 | Actuator + Micrometer | 헬스체크, Prometheus 지표 |
| API 문서 | springdoc-openapi (Swagger) | 코드에서 API 명세서 자동 생성 |
| 로그 | Logback + JSON 출력 | Loki 검색용 JSON 로그 |
| 테스트 | JUnit 5, Mockito, Testcontainers | 단위 테스트, 실제 MariaDB·Redis 컨테이너로 통합 테스트 |

**비고**

1. Spring Boot는 개발 시작 시점의 4.2 최신 패치 버전 사용 (4.2.x는 2027년 12월까지 무료 지원 예정)
2. 로컬 테스트는 Colima 사용 시 Testcontainers가 Docker를 찾도록 연결 설정 추가 (`DOCKER_HOST` 등, README에 기록)

### 3. 프론트 구성

| 구분 | 선택 | 용도 |
|---|---|---|
| 기본 | React + Vite, TypeScript | 화면 개발, 타입 검사로 오류 미리 확인 |
| 화면 이동 | React Router | 경로별 화면 (`/`, `/login`, `/my` 등) |
| API 호출 | axios | JWT 헤더 자동 추가, 401 응답 시 로그인 화면 이동 |
| 상태 관리 | React 기본 기능 (Context) | 로그인 정보만 전역 관리, 별도 라이브러리 없음 |

### 4. 핵심 구현 설계

| 구분 | 설계 내용 | 이유 |
|---|---|---|
| 기본 키 | 모든 테이블 UUID (DB 자동 증가 번호 미사용), MariaDB `UUID` 형식에 UUID v7(시간 순서 UUID) 저장 | WAS 2대에서 동시에 생성해도 충돌 없음 |
| 비밀번호 | BCrypt 해시로 저장 (원래 비밀번호로 되돌릴 수 없음) | NFR-05, DB 유출 시 피해 최소화 |
| 로그인 토큰 (JWT) | 만료 2시간, 갱신 토큰 없이 재로그인. 회원 전용 요청마다 탈퇴 여부 확인 | 서버가 토큰을 보관하지 않아 지울 수 없으므로, 탈퇴 후 다른 기기에 남은 토큰 차단 (FR-06) |
| 비밀번호 재설정 | 재설정 토큰 발급 (해시로 저장, 15분 만료, 1회만 사용), 아이디 찾기·재설정 요청 IP당 하루 5회 제한 (Redis) | 본인 확인 없이 비밀번호가 바뀌는 것 방지 |
| 추천 결과 저장 | 레시피·레시피 재료·검색 기록을 하나의 트랜잭션으로 저장 | 중간 실패 시 일부만 저장되는 것 방지 |
| 추천 캐시 | 같은 입력은 Redis 캐시로 응답, Redis 장애 시 캐시 없이 Gemini 호출 | 응답 속도, Gemini 사용량 절약 |
| Gemini 응답 | 응답 형식을 JSON으로 지정, 형식 오류·실패·타임아웃 시 안내 메시지 표시, 실패한 요청은 추천 횟수 차감 안 함 | NFR-10, 실패로 인한 사용자 횟수 손해 방지 |
| 요청 제한 | 추천 횟수를 Redis에 저장해 WAS 간 공유 | WAS가 여러 대여도 하루 횟수 정확히 계산 |
| 인기 랭킹 | 레시피 이름 기준 집계 (공백 제거 후 비교), 클릭 시 해당 이름의 최근 레시피 표시 | 추천마다 레시피가 새로 저장되어, ID 기준이면 같은 요리가 따로 집계됨 |
| 비밀 정보 | JWT 키 등 필수 환경 변수가 없으면 서버 시작 차단 | 기본값·빈 키로 운영되는 사고 방지 |

### 5. 인프라 연동 구현 규칙

| 구분 | 구현 | 관련 설계 |
|---|---|---|
| 헬스체크 | `/actuator/health`에 DB 상태만 포함, Redis는 제외 | Redis 장애 시에도 WAS가 정상으로 판단되어 Nginx·배포에서 제외되지 않음 |
| 종료 | graceful shutdown: 처리 중 요청을 끝낸 뒤 종료 (최대 30초), 컨테이너 종료 대기 40초(`stop_grace_period`, Docker 기본 10초면 강제 종료됨) | 04 > 12. 배포 (롤링 무중단) |
| DB 연결 | 접속 주소 `localhost:3306`(HAProxy), 커넥션 풀 10개, 사용 전 연결 검사, 연결 유지 시간은 HAProxy 유휴 시간(30분)보다 짧게 | 04 > 6. HAProxy (DB 전환 시 끊긴 연결 교체) |
| Redis 연결 | 타임아웃 1초, 실패 시 Redis 없이 처리 (캐시 생략, 요청 제한 미적용, 랭킹 숨김) | 02 장애 대응, 04 > 7. Redis |
| 사용자 IP | LB가 보낸 `X-Forwarded-For`에서 실제 IP 확인 (LB 주소에서 온 값만 신뢰) | IP별 추천 횟수 제한 (FR-09) |
| 응답 헤더 | `X-Served-By`: 서버 호스트명 (예: `cookit-was01`), `X-Request-ID`: LB에서 받은 요청 ID 그대로 반환 | FR-13, 04 > 10. 로그 |
| 로그 | JSON 형식, 모든 로그에 요청 ID 포함, 비밀번호·토큰·API 키 마스킹 | 04 > 10. 로그 |
| 지표 | 추천 요청 수, 캐시 적중 수, Gemini 호출 시간·실패 수를 지표로 기록 | 04 > 11. 알림 규칙 (Gemini 실패 증가) |
| DB 변경 | Flyway로 컬럼 추가 위주 변경 (삭제·이름 변경은 다음 배포에서 분리) | 04 > 12. 배포 (롤링 중 구버전 동작) |
| 시간대 | Asia/Seoul 고정 | 요청 제한 자정 기준, NFR-11 |
| CORS | 별도 설정 없음 (운영은 Nginx로 화면·API가 같은 도메인, 개발은 Vite 개발 서버가 API 전달) | 다른 도메인 간 요청 허용 설정이 필요 없는 구조 |
| 테스트용 설정 | Gemini mock 사용, 추천 횟수 제한 해제를 환경 변수로 전환 (기본값 꺼짐), 켜진 상태로 시작하면 경고 로그 출력 | 09 > 2. 공통 준비·측정 방법 (운영 서버에서 테스트 중에만 사용, 끄는 것을 잊는 실수 방지) |

### 6. 완료 기준

1. 기능 요구사항 FR-01~14 동작 확인 (로컬)
2. Swagger에서 API 25개 명세 확인
3. 단위·통합 테스트 통과
4. Docker 이미지로 `dev` 프로필 실행 정상, `prod` 프로필 설정값(필요한 환경 변수 목록) 확인
