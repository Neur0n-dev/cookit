# 00. 프로젝트 개요

> LLM 기반 레시피 추천 서비스 cookit을 Spring Boot + React로 개발해
> 온프레미스 가상화 환경에 단일 구성(VM 4대)으로 구축한 뒤, HTTPS 적용과 고가용성(HA) 이중화(VM 7대)로 고도화하고
> 통합 모니터링·무중단 배포(CI/CD)까지 구축·운영한 인프라 프로젝트.

## 배경

- 서버 1대로 운영하는 서비스는 서버 장애 시 서비스 전체 중단
- 배포할 때마다 재시작으로 순간 중단 발생
- 모니터링·알림이 없으면 장애를 사용자 문의로만 인지
- 위 문제를 해결하는 구조를 단계적으로 직접 설계·구축·운영

## 목적

- 실무 수준의 환경에서 서비스 직접 구축 및 운영
- 단일 구성 → HTTPS 적용 → 이중화 순서로 단계적 고도화, 이중화 전후 가용성·중단 시간 비교
- 이중화, 모니터링, 무중단 배포, 장애 대응 실제 검증
- Ansible 기반 인프라 코드화(IaC)로 재현 가능한 서버 환경 구성
- 기획부터 설계·구축·운영·회고까지 서비스 전 과정 단독 수행
- 결과물의 인프라 포트폴리오 정리

## 범위

| 구분 | 내용 |
|---|---|
| 1단계 단일 구성 | 서비스 개발(cookit), 서버 4대(LB·WAS·DB·모니터링 각 1대) 구축, Ansible 자동화, CI/CD 자동 배포, 모니터링·알림, HTTP(80) 서비스 |
| 2단계 HTTPS 적용 | Let's Encrypt 인증서(certbot 자동 갱신), 443 전환, 80 → 443 리다이렉트, 인증서 만료 알림 |
| 3단계 이중화 | 서버 3대 추가(총 7대), LB(keepalived VIP)·WAS·DB(Galera) 이중화, 롤링 무중단 배포, 장애 테스트 |
| 이후 단계 | 소셜 로그인, AWS 이전, 쿠버네티스 전환 |
| 환경 | 온프레미스 가상화 환경 (1·2단계 VM 4대 → 3단계 VM 7대) |
| 일정 | 개인 시간에 맞춰 단계별 순차 진행 (기간 미지정), 1단계 → 2단계 → 3단계 순서로 진행 |

## 완료 기준

### 1단계 단일 구성

| 구분 | 목표 | 측정 방법 |
|---|---|---|
| 서비스 동작 | 기능 요구사항(FR-01~14) 전체 정상 동작 | 기능별 시나리오 수동 점검 |
| 자동 배포 | main 브랜치 반영 시 수동 작업 없이 배포 완료<br>(배포 중 순간 중단 허용) | GitHub Actions 실행 결과, 배포 후 버전 확인 |
| 알림 | 장애 발생 후 3분 이내 Slack 수신 | 서버 중지 시각과 알림 수신 시각 비교 |
| 재현성 | VM 생성 이후 수동 작업 없이 Ansible로 4대 구성 완료 | 초기화된 VM에 playbook 실행 후 서비스 정상 동작 확인 |
| 성능 | 일반 API p95 500ms 이내 (동시 사용자 50명)<br>추천 캐시 적중 시 p95 200ms 이내 | k6 부하 테스트, Spring Boot 응답시간 지표 |
| 한계 확인 | LB·WAS·DB 각 1대 중지 시 서비스 중단 확인 및 중단 시간 기록<br>(3단계 비교 기준값) | blackbox_exporter 접속 실패 구간 |

### 2단계 HTTPS 적용

| 구분 | 목표 | 측정 방법 |
|---|---|---|
| HTTPS 접속 | 443 접속 시 유효한 인증서로 정상 응답<br>80 접속 시 443으로 리다이렉트 | 브라우저·curl 접속 확인 |
| 만료 알림 | 인증서 만료 14일 전·3일 전 Slack 수신 | 알림 기준일을 임시로 조정해 발송 확인 |
| 성능 | 1단계 성능 기준 유지 | 1단계와 동일 조건 k6 부하 테스트 |

### 3단계 이중화

| 구분 | 목표 | 측정 방법 |
|---|---|---|
| 장애 전환 | 서버 1대 장애 시 서비스 중단 시간<br>LB 5초 · WAS 10초 · DB 30초 이내 | blackbox_exporter 접속 실패 구간<br>(장애 테스트 중 1초 간격 측정) |
| 가용성 | 장애 테스트 3종(LB·WAS·DB 각 1대 중지)을 포함한 24시간 가용성 99.5% 이상<br>(중단 허용 약 7분) | blackbox_exporter 24시간 접속 성공률 |
| 무중단 배포 | 롤링 배포 중 5xx 에러 0건 | 배포 중 k6로 초당 10요청 지속 호출, 실패 건수 집계 |
| 재현성 | VM 생성 이후 수동 작업 없이 Ansible로 7대 구성 완료 | 초기화된 VM에 playbook 실행 후 서비스 정상 동작 확인 |
| 성능 | 1단계 성능 기준 유지 | 1단계와 동일 조건 k6 부하 테스트 |
